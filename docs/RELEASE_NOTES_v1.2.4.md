# Akagi-NG v1.2.4

本版本重点修复 FlyA 有状态会话与实际游戏动作不同步导致的
`state_replay_invalid`，恢复并加固雀魂自动加入流程，同时补齐插件运行时、代理路由与发布质量门验证。

## FlyA 与雀魂状态修复

- 当 FlyA 推荐的舍牌、拔北或两阶段立直没有在游戏界面中实际执行，或用户手动执行了不同动作时，Akagi-NG 会将真实事件与待执行建议进行核对，并在下一次请求前轮换 FlyA 会话、完整重放已观测状态；若预期动作完全没有出现在事件流中，则停用本小局的远程重放并在下一次完整 `start_kyoku` 恢复。
- FlyA 请求超时、取消、响应丢失或响应验证失败后，不再复用结果不确定的有状态会话；客户端会保留 HTTP 熔断退避状态，仅轮换服务端会话标识，避免晚到响应与本地 Mortal 回退动作再次造成分叉。
- 修复雀魂庄家起手 14 张牌被整体排序后，将排序末尾误当作真实摸牌的问题。现在只排序前 13 张手牌并保留协议中的第 14 张牌身份，从源头保证 `tsumogiri`（摸切）语义正确。
- 连续拔北仍按正常 MJAI 事件发送并保留界面就绪下限。日志中的连续两次拔北请求均返回 HTTP 200；本次 HTTP 400 的真实原因是后续 FlyA 建议打 `S`、界面实际打出 `F` 后继续复用已分叉会话。
- FlyA 拒绝状态重放时，会在 `<userData>/logs/flya-replay/` 生成经过字段白名单过滤的诊断 JSON，并记录安全的序列范围、状态摘要和尾部事件。诊断文件不包含 API Key 或 HTTP 请求头。
- 对只有一个合法动作的局面启用 libriichi quick evaluation，避免强制动作浪费一次在线/本地推理；立直前瞻会把强制舍牌显示为 100% 候选。

## 自动打牌与自动加入

- 恢复雀魂“自动加入下一场”，并增加协议大厅事件、目标窗口稳定性、双视觉锚点、结算按钮定点检测以及匹配开始协议确认；无法识别新版界面时会安全中止，不执行固定坐标点击。
- 人工提前开始匹配会立即取消后台剩余点击，匹配期间重复到达的大厅事件也不会再次调度坐标操作。
- 新增“完成对局数上限”；设为 `0` 表示不限制，达到上限后停止自动加入，关闭后重新启用会开始新的计数周期。
- 改进金之间、玉之间、王座之间的滚动与点击坐标，并补充日文、中文及常见英文雀魂窗口标题。
- 自动打牌继续支持舍牌、立直、吃碰杠、和牌、流局、拔北和跳过等推荐动作。该功能通过 Windows 输入模拟执行，使用前请在“自动化”页面确认目标窗口与延迟设置。

## 插件系统

- 已针对发行包验证独立插件仓库的远程目录、SHA-256 下载校验、安装、启用、互斥与重启恢复流程。
- 一番街本地解锁插件 `v0.1.8` 使用 Akagi-NG 已打包的 `ruamel.yaml`，不需要也不应要求用户运行 `pip install PyYAML`。如果旧插件仍提示缺少 PyYAML，请在“扩展工具”中更新插件并重启 Akagi-NG。
- 插件与 Akagi-NG 主程序使用独立版本号。插件升级不会改变 Akagi-NG 的 `1.2.4` 版本，也不会覆盖 `<userData>/config/plugins/<plugin-id>/` 中的配置；插件自身若依赖新版 API，仍需按其发布说明升级主程序。

## 网络与平台识别

- 将直连 IP 的雀魂 `/gateway` WebSocket 识别为雀魂协议，避免因设置页残留的平台选择而创建错误 Bridge。
- 当 Clash Verge 被配置为 Akagi-NG 的上游代理时，`verge-mihomo.exe` 会在游戏域名规则之前直连，阻止流量重新进入 Akagi-NG TUN 形成代理回环。

## 质量门

- 增加 FlyA 动作核对与诊断文件、庄家第 14 张牌、自动加入生命周期与局数限制、强制动作、直连 IP 路由、mihomo 代理绕行等回归测试。
- GitHub Actions 新增日志管道韧性、mihomo 配置、桌面权限边界和 Windows 成品包 Electron 信任边界检查。
- Codecov 上传目标已切换到 `FanhuaAwA/Akagi-NG`，发布工作流使用本版本说明生成 Release。

## 下载与升级

请根据操作系统下载 Windows、Linux 或 macOS 对应的 `v1.2.4` 构建产物。配置、日志和插件均保存在操作系统的 `<userData>` 目录中；替换旧的程序目录不会删除这些运行数据。

> 自动打牌、自动加入及解锁类插件可能违反游戏平台服务条款，请仅在理解风险后使用。
