# Akagi-NG v1.2.6

本版本修复三项问题：FlyA 在线模型在连续对局间因事件流跨局累积而触发 `state_replay_invalid` 拒绝；自动加入在雀魂客户端 UI 更新后卡在"大厅就绪检测"不再继续；以及通知栏偶尔出现"蓝色空白通知"。

## FlyA 在线模型

- 修复 FlyA 有状态会话在连续自动打牌时跨局累积事件的问题。现在每一局结束（`end_kyoku`）后都会从全新的 `start_game` 边界重建事件流，与断流/重连的恢复路径一致，避免长时间多局会话触发 `state_replay_invalid` 拒绝。
- 决策请求的协议结构升级为 `flya-mahjong-events-v2`，并停止发送可选的 `state_digest` 字段，改由服务器自行校验，消除潜在的 `state_digest_mismatch` 来源。

## 自动加入

- 修复自动加入在点击结算确认后停滞的问题：当雀魂客户端更新导致大厅视觉锚点漂移时，大厅就绪检测现在会在有限的锚点尝试窗口后回退到"窗口几何稳定"的坐标判定，继续执行段位场、房间、模式的点击链，而不再中止。
- 重新校准了段位场、各房间（铜/银/金/玉/王座）以及四人东/南、三人东/南按钮的坐标，适配当前雀魂客户端布局（玉、王座为向下滑动后的位置）。
- 大厅锚点采样现在会记录实际测量到的颜色，便于未来客户端再更新时快速校准。

## 通知

- 修复偶尔出现的"蓝色空白通知"：`lobby_ready`（大厅就绪）和 `matching_started`（匹配开始）这两个通知此前缺少前端配置与翻译文案，现已在简体中文、繁体中文、英文、日文四种语言下补齐，分别显示为绿色"大厅已就绪"和蓝色"正在匹配…"。

## 质量门

- 新增 FlyA 端局间事件流重建、自动加入坐标兜底两组回归测试。
- 全部 668 项后端测试、TypeScript 类型检查、ESLint 与 Prettier 检查通过。

## 下载与升级

请根据操作系统下载 Windows、Linux 或 macOS 对应的 `v1.2.6` 构建产物。配置、日志和插件均保存在操作系统的 `<userData>` 目录中；替换旧的程序目录不会删除这些运行数据。

> 自动打牌、自动加入及解锁类插件可能违反游戏平台服务条款，请仅在理解风险后使用。
