# Akagi-NG v1.2.5

本版本将后端启动改为事务式：真实端口绑定成功、健康检查通过后，Electron 桌面端才会进入就绪状态；同时新增 Creem 支付渠道，并让数据服务器端口回退时前端自动跟随实际绑定端口。

## 启动可靠性与生命周期

- 数据服务器（DataServer）启动改为事务式：主后端现在等待真实 socket 绑定成功后才继续，启动失败立即退出，并为每个被拒绝的候选端口保留原生 `errno`/Windows 错误详情，替代原先只显示通用超时的做法。
- Electron 端用带认证的 `/api/health` 就绪检查取代通用超时轮询，包含 PID 校验、受限的 stderr 诊断信息，并把具体启动错误直接显示到仪表盘。
- 可选的 Mihomo TUN 启动排队在认证健康检查通过之后；当数据服务器回退到备用端口时，前端 API/SSE 连接会自动指向实际绑定端口。
- 桌面端后端就绪超时延长至 60 秒，为慢速机器上的首次 torch 导入留出时间。

## 支付渠道

- OT3/FlyA 购买新增 Creem 渠道（与 PayPal 并列）：支持创建结账会话、结果轮询，并在设置页新增完整的结账对话框流程。
- OT3 健康检查改为上报聚合队列深度与工作进程存活状态，并兼容旧版按模型返回的队列格式。

## 自动打牌

- 修正动作规划器对 `kita` 事件的处理：统一归一化为 `nukidora`，确保三麻拔北同时被两个 MJAI 消费端正确识别。

## 前端

- 仪表盘改为在解析到实际后端端点后再渲染，避免占位配置与实际绑定端口不一致导致 API/SSE 请求走错端口。
- 设置页 OT3 服务面板按 FlyA / OT3 两种服务分别展示健康信息（模型数 / 队列深度与工作进程状态）。

## 质量门

- 新增回归测试：端口范围耗尽、Windows 风格绑定权限失败、端口回退持久化、后端退出/错误传播、健康身份校验、后端先于 Mihomo 的启动顺序，以及 Creem 结账解析。

## 下载与升级

请根据操作系统下载 Windows、Linux 或 macOS 对应的 `v1.2.5` 构建产物。配置、日志和插件均保存在操作系统的 `<userData>` 目录中；替换旧的程序目录不会删除这些运行数据。

> 自动打牌、自动加入及解锁类插件可能违反游戏平台服务条款，请仅在理解风险后使用。
